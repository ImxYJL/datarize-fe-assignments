# 프로젝트 개요

- 대시보드 MVP를 개발한다고 생각하며 과제를 진행했습니다. MVP인 만큼 모든 기능을 개발하되 추후 리팩토링에 열려 있어야 한다고 생각했고, 이를 위해 전반적인 가독성을 중시했습니다.

- 반복되는 컴포넌트는 최대한 추출해 JSX 가독성을 높이려고 했고, 로직이나 컴포넌트 간의 의존성을 낮추고자 했습니다.

## 프로젝트 설정 및 실행 방법

```md
# 레포지토리 클론

git clone https://github.com/ImxYJL/datarize-fe-assignments.git

# 의존성 설치 (모노레포 환경 주의사항 포함)

cd frontend
yarn install

# 개발 서버 실행

yarn start-server  
yarn start-client
```

## 기술 스택

- **Zustand**: 전역 상태 관리를 통해 props drilling을 최소화하고 리렌더링을 최적화합니다.
- **TanStack Query**: 서버 상태를 선언적으로 관리하고, 간단한 캐싱 기능 사용합니다.
- **Tailwind**: 빠른 스타일 적용을 위해 사용했습니다.

## 상태 관리

### 전역 상태

- Zustand를 통해, `FilterStore`에서 **사용자가 선택한 날짜값과 선택한 고객의 id**를 전역 상태로 관리하고 있습니다.

  - 날짜값

    - 날짜값의 변경으로 현존하는 모든 section의 데이터가 변하고, 추후 전체 데이터 fetch에 영향을 미칠 수 있는 다른 필터 값이 추가될 수도 있다고 생각해 훅 이름을 `useFilterStore`라고 지었습니다.
    - 많은 컴포넌트에서 사용되는 만큼 현재와 미래의 props drilling을 해소할 수 있어서 분리했습니다.

  - 선택한 고객 id
    - 사실 날짜값에 비해 덜 전역적이고 로컬 상태로도 충분히 구현할 수 있습니다.
    - 그러나 현재 구조에서 이 값을 `Dashboard` 컴포넌트(각 섹션을 모두 모아 렌더하는 메인 컴포넌트)에서 관리한다면, 이 값이 변할 때 이 값을 사용하지 않는 컴포넌트까지 리렌더링되기에 전역 스토어에 두고 날짜값과 별도로 select해오도록 작성했습니다.

### 서버 상태

- API 호출을 통해 받아오는 데이터의 대부분은 TanStack을 사용해 서버 상태로 관리합니다.
- csv는 TanStack이 제공하는 전역성, 로딩 상태 관리, 캐싱 등이 필요하지 않으므로 TanStack으로 불러오지 않았습니다.

- 서버의 순수 데이터를 UI 친화적인 형식으로 가공하는 과정을 `select` 옵션에서 수행해 UI에 실제로 렌더링할 값을 캐싱했습니다.

### 로컬 상태

고객 목록 정렬 및 검색, 페이지네이션에 필요한 값들은 현재로서는 고객 목록에서만 사용하는 로컬 값이라고 생각해 전역 스토어 대신 useState를 사용해 제공합니다.

## 고객 목록 정렬 기능

### 정렬 관련 컴포넌트

- 정렬 기준은 추후에 다양한 옵션들이 추가될 수 있다고 생각해 처음에는 드롭다운을 고려했습니다.
- 하지만 드롭다운 컴포넌트를 타입 안전하게 사용하기 위해서는 타입 유틸 함수가 필요한데, MVP 단계에서는 이것까지 고려하기에는 범위상이나 일정상이나 적절하지 않다고 생각했습니다.
- 따라서 지금은 요구사항에 맞게 간단한 탭으로 정렬 기준을 선택하고 있습니다.
  - 내림차/오름차 버튼은 정렬 기준이 금액순일 때만 활성화됩니다.

### 페이지네이션

- 무한 스크롤 방식과 페이지를 넘기는 방식을 고민했으나, 유저 데이터가 많아질 수 있는 환경에서는 무한 스크롤보다는 페이지를 명시적으로 안내하는 UI가 성능 면에서도 보기에도 좋다고 생각해 페이지를 넘길 수 있도록 구현했습니다.
- 페이지를 이동하는 UI를 선택했으므로, 불필요한 조기 최적화 대신 key prop을 넘겨주는 기본 최적화만 진행했습니다.
